# Universal Mobile Compute Fabric (UMCF) — Functional Requirements Specification

> [!IMPORTANT]
> This specification defines the complete set of **80 normative Functional Requirements (`FR-001` through `FR-080`)** for UMCF, organized across the **8 Roadmap Stages (`S1` through `S8`)**. Every requirement is assigned a MoSCoW priority (`P0 = Must Have`, `P1 = Should Have`), target component(s), and deterministic acceptance criteria.

---

## Stage 1: Foundation, Identity, Security & Wire Protocol (`FR-001` – `FR-010`)

| Req ID | Priority | Requirement Statement | Acceptance Criteria | Target Component(s) |
| :--- | :---: | :--- | :--- | :--- |
| **`FR-001`** | `P0` | **Ed25519 Node Identity Generation**: Every node SHALL generate a unique Ed25519 cryptographic keypair on first initialization and derive its canonical `NodeId` (`umcf1_<base32(blake3(pubkey)[0..20])>`). | Calling `IdentityProvider::init()` produces a valid 32-byte Ed25519 public key, derives a deterministic `umcf1_` prefix ID, and persists the private key securely. | `umcf-core` |
| **`FR-002`** | `P0` | **Hardware-Backed Keystore Persistence**: Private identity keys SHALL be stored in the platform's secure enclave/keystore (Android Keystore, iOS Keychain, Windows DPAPI, macOS Keychain, Linux Secret Service / encrypted `0600` keyfile) and zeroized in RAM on drop. | Key reload across process restarts yields identical `NodeId`; memory dump check verifies `ZeroizeOnDrop` clears raw private key buffers. | `umcf-core` |
| **`FR-003`** | `P0` | **Versioned Wire Framing & CRC32C Integrity**: All peer-to-peer messages SHALL be encapsulated in a 16-byte fixed header (`Magic=0x554D`, `Version=1`, `Flags`, `MessageType`, `PayloadLength`, `HeaderCRC32C`) followed by the serialized payload. | Corrupted headers or mismatched `Magic`/`Version` bytes are deterministically rejected with `ProtoError::CrcMismatch` or `ProtoError::UnsupportedVersion`. | `umcf-proto` |
| **`FR-004`** | `P0` | **Signed Wire Envelopes**: All state-mutating `WireEnvelope<T>` payloads SHALL include an Ed25519 signature over canonical bytes of `(version, message_id, correlation_id, sender_node_id, lease_epoch, timestamp_unix_ms, payload)`. | Any tampered field in `WireEnvelope` causes `verify_envelope()` to return `ProtoError::SignatureVerificationFailed` in `< 1ms`. | `umcf-proto`, `umcf-core` |
| **`FR-005`** | `P0` | **QR Code & URI Cluster Enrollment**: A Master/Coordinator node SHALL generate a signed, time-bounded (`<= 120s` TTL) enrollment payload (`umcf://enroll?...`) renderable as a QR code for one-scan peer onboarding. | Scanning or importing an unexpired QR payload completes mutual attestation and issues a cluster membership certificate; expired or replayed nonces are rejected. | `umcf-core`, `apps/mobile-desktop` |
| **`FR-006`** | `P0` | **RBAC Capability Token Issuance & Enforcement**: The cluster root authority SHALL issue scoped, time-bounded capability tokens (`cluster:admin`, `job:submit`, `worker:join`, `stream:view`, `stream:input`, `cas:read`, `cas:write`). | Requests lacking the required `CapabilityScope` for an endpoint or RPC are rejected with `CoreError::InsufficientScope`. | `umcf-core`, `umcf-coordinator` |
| **`FR-007`** | `P0` | **Peer Revocation & Quarantine List**: Cluster administrators SHALL be able to revoke a compromised or lost `NodeId`, immediately terminating its active QUIC sessions and rejecting future handshakes. | Adding a `NodeId` to the signed `RevocationList` closes all active streams from that peer within `< 500ms` across all cluster nodes. | `umcf-core`, `umcf-coordinator` |
| **`FR-008`** | `P0` | **Control Frame Size Enforcement**: Control Plane channels SHALL enforce a strict `64 KiB` (`65,536` bytes) maximum frame size to prevent memory exhaustion and enforce data-plane separation. | Any Control Plane frame with `PayloadLength > 65536` is rejected before buffer allocation with `ProtoError::FrameTooLarge`. | `umcf-proto`, `services/control-plane-*` |
| **`FR-009`** | `P1` | **Replay Attack Prevention Window**: Nodes SHALL reject signed control envelopes whose `timestamp_unix_ms` drifts more than `±60,000ms` from synchronized cluster time or whose `message_id` has been seen within the deduplication window. | Duplicate `message_id` or stale timestamp (`> 60s`) envelopes are dropped with `SecurityError::ReplayDetected`. | `umcf-core` |
| **`FR-010`** | `P1` | **Structured Security Audit Logging**: All enrollment events, role elections, token revocations, and authentication failures SHALL be recorded in an append-only local and coordinator audit log. | Security events emit structured JSON audit records containing `timestamp`, `actor_node_id`, `event_type`, and `outcome`. | `umcf-core`, `umcf-coordinator` |

## Stage 2: Mesh Networking, Discovery, NAT Traversal & Control Plane (`FR-011` – `FR-020`)

| Req ID | Priority | Requirement Statement | Acceptance Criteria | Target Component(s) |
| :--- | :---: | :--- | :--- | :--- |
| **`FR-011`** | `P0` | **Zero-Configuration LAN mDNS Discovery**: Native nodes on the same local subnet SHALL automatically advertise and discover peers via UDP multicast DNS (`_umcf._udp.local`) without internet access. | Two nodes on the same LAN subnet discover each other's IP/port and `NodeId` within `<= 2,000ms` of startup with WAN disconnected. | `umcf-core` |
| **`FR-012`** | `P0` | **Direct P2P QUIC Transport with mTLS**: Peers SHALL establish multiplexed QUIC (`quinn`) connections authenticated via mutual Ed25519 keys pinned to the cluster registry. | Peers establish encrypted bidirectional streams and datagrams; unknown `NodeId` certificates are rejected during the TLS handshake. | `umcf-core` |
| **`FR-013`** | `P0` | **Cloudflare Workers + Durable Objects Primary Control Plane**: The primary WAN Control Plane SHALL coordinate cluster state, WebSocket signaling, and ICE candidate exchange via per-cluster Cloudflare Durable Objects. | Nodes behind separate WAN routers register, exchange ICE candidates, and receive cluster topology updates via `services/control-plane-cf`. | `services/control-plane-cf` |
| **`FR-014`** | `P0` | **Google Cloud Run Control Plane Failover**: Clients SHALL automatically fail over to the stateless Google Cloud Run coordinator (`services/control-plane-cloudrun`) if the primary Cloudflare endpoint returns HTTP `5xx` or times out (`> 3,000ms`). | Simulating a primary control plane outage triggers client failover to the secondary endpoint within `<= 3,500ms` without dropping active Data Plane QUIC streams. | `services/control-plane-cloudrun`, `umcf-core` |
| **`FR-015`** | `P0` | **STUN Endpoint Discovery & NAT Classification**: WAN-connected nodes SHALL query STUN servers to discover their server-reflexive IP:port and classify local NAT behavior (Full Cone, Restricted, Symmetric). | Node accurately reports its `EndpointCandidate::ServerReflexive` address and `NatType` in its `ResourceProfile`. | `umcf-core` |
| **`FR-016`** | `P0` | **Simultaneous UDP Hole-Punching**: Peers behind traversable NATs SHALL execute synchronized UDP hole-punching using exchanged ICE candidates to establish direct WAN QUIC sessions. | Peers behind Cone / Port-Restricted NATs establish a direct P2P QUIC connection within `<= 600ms` of candidate exchange. | `umcf-core` |
| **`FR-017`** | `P0` | **Encrypted TURN / DERP-Style Relay Fallback**: When direct UDP hole-punching fails (e.g., Symmetric CGNAT or UDP-blocking firewall), nodes SHALL automatically route end-to-end encrypted QUIC frames through an authorized relay node. | Under simulated Symmetric NAT (`nftables` drop direct UDP), peers establish connectivity via the relay within `<= 900ms` while preserving end-to-end mTLS encryption. | `umcf-core` |
| **`FR-018`** | `P0` | **QUIC Stream Priority Multiplexing**: Data Plane connections SHALL enforce 5 distinct priority tiers (`0=Control`, `1=Input`, `2=AI/RealtimeVideo`, `3=MediaTranscode`, `4=CASBulk`) over a single QUIC connection. | Saturating a link with priority `4` CAS transfers increases priority `0`/`1`/`2` stream P99 latency by `< 3ms`. | `umcf-core` |
| **`FR-019`** | `P1` | **Continuous Link Quality Matrix Probing**: Connected peers SHALL measure rolling RTT, jitter, packet loss, and available bandwidth (`PeerLinkMetrics`) and report changes to the coordinator. | `PeerLinkMatrix` updates reflect injected `tc netem` latency/loss changes within `<= 3,000ms`. | `umcf-core`, `umcf-coordinator` |
| **`FR-020`** | `P1` | **Seamless Connection Migration & Path Upgrade**: Active QUIC sessions SHALL survive IP address changes (Wi-Fi to cellular roaming) and automatically upgrade from Relay paths to Direct P2P paths when background hole-punching succeeds. | Changing a worker's source IP or opening a direct LAN path migrates the QUIC connection without aborting an in-flight inference task lease. | `umcf-core` |

## Stage 3: Hardware Discovery, Calibration & Dynamic Role Governance (`FR-021` – `FR-030`)

| Req ID | Priority | Requirement Statement | Acceptance Criteria | Target Component(s) |
| :--- | :---: | :--- | :--- | :--- |
| **`FR-021`** | `P0` | **Cross-Platform CPU & Memory Enumeration**: Every node SHALL detect CPU architecture (`x86_64`, `aarch64`, `wasm32`), SIMD extensions (`AVX2`, `AVX-512`, `NEON`), logical/performance core counts, total RAM, and available RAM. | `ResourceProfile` accurately populates CPU and RAM metrics across Windows, Linux, macOS, Android, iOS, and Web targets. | `umcf-core`, `umcf-worker` |
| **`FR-022`** | `P0` | **Heterogeneous Accelerator Enumeration**: Nodes SHALL enumerate available GPU and NPU compute backends (`CUDA`, `ROCm`, `Metal`, `Vulkan`, `DirectX 12`, `QNN`, `WebGPU`) including dedicated/unified VRAM capacity. | `ResourceProfile.accelerators` lists all compatible hardware devices with vendor ID, model name, backend type, and allocatable VRAM. | `umcf-core`, `umcf-worker` |
| **`FR-023`** | `P0` | **Deterministic Hardware Calibration Micro-Benchmark**: Upon enrollment or hardware change, workers SHALL execute a bounded (`<= 1,500ms`) memory-bandwidth and matrix-multiplication micro-benchmark and sign the resulting `CalibrationAttestation`. | Calibration completes in `< 1.5s`, records sustained `memory_bandwidth_gbps` and `int4_tok_per_sec_calibrated`, and caches results for 7 days. | `umcf-worker` |
| **`FR-024`** | `P0` | **Mobile Memory Safety Watermark (`<= 75%` Free RAM)**: On Android and iOS, `allocatable_ram_bytes` SHALL be strictly capped at `<= 75%` of currently available system RAM to prevent OS OOM kills (`lmkd` / Jetsam). | Attempting to configure or accept a lease exceeding `0.75 * available_ram_bytes` on mobile is rejected with `WorkerError::MemoryBudgetExceeded`. | `umcf-core`, `umcf-worker` |
| **`FR-025`** | `P0` | **Real-Time Thermal & Battery Telemetry Polling**: Workers SHALL sample battery percentage, AC charging state, power draw, and thermal status (`Nominal`, `Fair`, `Serious`, `Critical`) every `1,000ms`. | `WorkerHeartbeat` includes fresh `PowerState` and `ThermalState` readings every second. | `umcf-core`, `umcf-worker` |
| **`FR-026`** | `P0` | **Automatic Thermal & Battery Circuit Breaker**: When a node enters `ThermalState::Critical` (`>= 43°C` battery / `>= 85°C` die) or unplugged battery `< 20%`, it SHALL transition to `NodeRole::Draining` within `500ms` and refuse new task admissions. | Injecting a critical thermal or low-battery state transitions the node to `Draining` in `< 500ms` and sends a `TaskPreemptNotice` to the coordinator. | `umcf-worker` |
| **`FR-027`** | `P0` | **Dynamic Master / Worker / Hybrid Role State Machine**: Nodes SHALL dynamically transition between `Worker`, `Master`, `Hybrid`, and `Draining` roles based on cluster size, power state, and coordinator availability. | A single desktop node boots as `Hybrid`; joining mobile nodes become `Worker`; if cluster exceeds 16 nodes, the highest-scoring node transitions to dedicated `Master`. | `umcf-coordinator`, `umcf-core` |
| **`FR-028`** | `P0` | **Autonomous Coordinator Election & Monotonic Lease Fencing**: When WAN is unreachable or the current Master lease expires, surviving nodes SHALL elect a new Master using the deterministic `ElectionScore` function and increment `lease_epoch: u64`. | Killing the active Master triggers re-election within `<= 5,000ms` on LAN; stale commands with an older `lease_epoch` are rejected by all workers. | `umcf-coordinator` |
| **`FR-029`** | `P1` | **Graceful Master Leadership Handover**: When an active `Master` or `Hybrid` node is paused by the user or enters `Draining`, it SHALL transfer the cluster state snapshot and increment `lease_epoch` to the next highest-scoring node before shutting down. | Graceful stop of the Master node completes leadership transfer in `< 500ms` with zero interrupted worker task leases. | `umcf-coordinator` |
| **`FR-030`** | `P1` | **User-Configurable Resource Envelopes**: Users SHALL be able to set per-device maximum RAM, CPU thread count, GPU VRAM percentage, and "Only run when charging" policies via CLI or UI. | Updating the user resource policy immediately clamps `ResourceProfile.allocatable_ram_bytes` and triggers graceful rebalance if current usage exceeds the new cap. | `umcf-worker`, `apps/mobile-desktop` |

## Stage 4: Constraint-Based DAG Scheduler & Content-Addressed Storage (`FR-031` – `FR-040`)

| Req ID | Priority | Requirement Statement | Acceptance Criteria | Target Component(s) |
| :--- | :---: | :--- | :--- | :--- |
| **`FR-031`** | `P0` | **Heterogeneous DAG Job Representation**: `umcf-scheduler` SHALL represent jobs as validated Directed Acyclic Graphs (DAGs) of typed stages with explicit memory, compute backend, and inter-stage bandwidth requirements. | Submitting a job with a cycle is rejected with `SchedulerError::CyclicDagDetected`; valid linear and branching DAGs parse into `JobGraph`. | `umcf-scheduler` |
| **`FR-032`** | `P0` | **Memory & Capability Constraint Solver**: The scheduler SHALL only assign a DAG stage to a node if the node supports the required `ComputeBackend` and has `allocatable_ram_bytes >= stage.required_memory_bytes`. | Across 1,000 randomized cluster/job fuzz tests, `compute_placement()` never overcommits any node's memory or assigns an unsupported backend. | `umcf-scheduler` |
| **`FR-033`** | `P0` | **Single-Node Colocation Preference Optimization**: When a single available node can accommodate the entire job within its memory budget and yields lower estimated latency than network-split execution, the scheduler SHALL colocate all stages on that node. | Given a 4 GB model and a desktop node with 12 GB free VRAM alongside 2 slow Wi-Fi phones, the scheduler assigns 100% of layers to the desktop node. | `umcf-scheduler` |
| **`FR-034`** | `P0` | **Bandwidth & Latency-Aware Pipeline Partitioning**: When multi-node partitioning is required, the scheduler SHALL assign stage weights proportional to calibrated compute throughput while minimizing cuts across slow/high-RTT WAN links. | In a cluster with 2 LAN nodes (`1ms` RTT) and 1 WAN node (`50ms` RTT), the solver places latency-critical sequential pipeline stages on the LAN pair first. | `umcf-scheduler` |
| **`FR-035`** | `P0` | **Incremental Mid-Job Fault Rebalancing**: When a worker disconnects or enters `Draining`, `umcf-scheduler` SHALL compute a minimal `RebalanceDelta` reassigning only the affected stage(s) without restarting unaffected upstream/downstream stages. | `IncrementalRebalance()` reassigns a failed middle pipeline stage to a standby node in `< 50ms` solver execution time. | `umcf-scheduler` |
| **`FR-036`** | `P0` | **BLAKE3 Content-Addressed Storage (CAS)**: `umcf-engine-storage` SHALL store and address all model weights, media segments, and shader artifacts by their 256-bit BLAKE3 Merkle root digest (`umcf_cas_<hex>`). | Storing identical files on different nodes produces the exact same `umcf_cas_` identifier and skips redundant transfers. | `umcf-engine-storage` |
| **`FR-037`** | `P0` | **4 MiB Chunk Swarming & Parallel Peer Fetching**: Files larger than `4 MiB` SHALL be split into `4 MiB` chunks, allowing a worker to fetch disjoint chunks concurrently from multiple LAN/WAN peers holding the blob. | A worker fetching a 64 MiB artifact from 2 seeding peers downloads chunks in parallel and verifies each chunk's BLAKE3 leaf hash upon receipt. | `umcf-engine-storage` |
| **`FR-038`** | `P0` | **Zero-Copy Memory-Mapped (`mmap`) Artifact Access**: Verified CAS blobs (such as GGUF model slices) SHALL support direct read-only OS memory mapping (`mmap`) into execution engines without duplicating buffers in heap memory. | Loading a 2 GB GGUF layer slice via `CasStore::mmap_range()` allocates `< 16 MiB` of private heap memory. | `umcf-engine-storage`, `umcf-engine-ai` |
| **`FR-039`** | `P1` | **LRU Cache Eviction with Pinning**: The CAS engine SHALL enforce a configurable disk quota per node, automatically evicting Least-Recently-Used (LRU) unpinned chunks while preserving blobs pinned by active task leases. | Filling the CAS store beyond its quota evicts oldest unpinned blobs while returning `CasError::BlobPinned` if eviction of an active lease blob is attempted. | `umcf-engine-storage` |
| **`FR-040`** | `P1` | **Resumable Interrupted Transfers**: If a peer disconnects during a multi-chunk CAS transfer, the receiver SHALL retain all verified `4 MiB` chunks and resume fetching only missing chunk indices from surviving peers. | Dropping a connection at 50% transfer completion and reconnecting transfers only the remaining 50% of chunks. | `umcf-engine-storage` |

## Stage 5: Distributed AI Inference Engine (`llama.cpp` / GGML) (`FR-041` – `FR-050`)

| Req ID | Priority | Requirement Statement | Acceptance Criteria | Target Component(s) |
| :--- | :---: | :--- | :--- | :--- |
| **`FR-041`** | `P0` | **GGUF Model Metadata Inspection & Layer Indexing**: `umcf-engine-ai` SHALL parse GGUF headers to extract architecture, layer count, hidden dimension, KV head count, quantization type, and exact byte offsets per layer tensor. | Inspecting a valid GGUF file returns complete `ModelManifest` without loading tensor weight payloads into RAM. | `umcf-engine-ai` |
| **`FR-042`** | `P0` | **Partial Layer-Range Weight Loading**: Each worker in a distributed inference pipeline SHALL load and allocate only its assigned transformer layer range `[start_layer..end_layer]` (plus embedding on stage 0 and norm/head on the final stage). | A worker assigned layers `10..19` of a 32-layer model consumes `< 35%` of the full model's weight memory footprint. | `umcf-engine-ai` |
| **`FR-043`** | `P0` | **QUIC RPC Activation Tensor Forwarding**: Pipeline workers SHALL stream intermediate hidden-state activation tensors (`TensorRpcForward`) directly from stage $i$ to stage $i+1$ over persistent QUIC streams. | Output logits of a 3-node partitioned pipeline match single-node execution within floating-point/quantization tolerance (`cosine_similarity >= 0.999`). | `umcf-engine-ai` |
| **`FR-044`** | `P0` | **Adaptive Activation Quantization (`FP16` / `Q8_0`)**: `umcf-engine-ai` SHALL support compressing inter-node activation tensors from `FP16` to `Q8_0` when peer link bandwidth is `< 100 Mbps` or RTT `> 10ms`. | Enabling `Q8_0` activation mode reduces `TensorRpcForward` wire payload size by `>= 45%` while maintaining coherent token generation. | `umcf-engine-ai` |
| **`FR-045`** | `P0` | **Distributed Session-Keyed KV-Cache Management**: Each pipeline worker SHALL maintain the local KV-cache tensors for its assigned layers keyed by `session_id`, supporting multi-turn conversation prefix reuse. | Sending a follow-up prompt in the same `session_id` reuses cached KV positions `0..N` and computes prefill only for new tokens `N..M`. | `umcf-engine-ai` |
| **`FR-046`** | `P0` | **Streaming Token & Logit Generation (OpenAI-Compatible API)**: The Coordinator / CLI / UI SHALL expose both native UMCF streaming events and an local OpenAI-compatible `/v1/chat/completions` SSE endpoint backed by the distributed fabric. | Standard OpenAI SDK / `curl` clients receive real-time Server-Sent Events (`data: {"choices":[{"delta":{"content":"..."}}]}`) from the distributed cluster. | `umcf-engine-ai`, `umcf-coordinator` |
| **`FR-047`** | `P0` | **Mid-Generation Worker Failure Recovery via Prompt Replay / KV Sync**: If an intermediate pipeline worker fails or throttles mid-generation, the pipeline SHALL recover on a replacement worker via KV-cache transfer or batched token history prefill without dropping the user's stream. | Killing Worker 2 at token #25 of a 50-token generation pauses output for `<= 1,500ms` and seamlessly streams tokens #26..#50 to the client. | `umcf-engine-ai`, `umcf-scheduler` |
| **`FR-048`** | `P1` | **Multi-Request Pipeline Micro-Batching**: When multiple inference requests are active concurrently, pipeline stages SHALL overlap execution (Stage 2 computes Request A while Stage 1 computes Request B) to maximize cluster utilization. | Running 3 concurrent requests across a 3-node pipeline achieves `>= 1.8x` aggregate token throughput compared to serial single-request execution. | `umcf-engine-ai`, `umcf-scheduler` |
| **`FR-049`** | `P1` | **Speculative Decoding Support**: The engine SHALL support running a lightweight draft model on the head/tail node to propose $K$ candidate tokens verified in a single batched pass across the distributed pipeline. | Speculative decoding (`K=4`) reduces network round-trips per accepted token by `>= 40%` on high-RTT (`25ms`) links. | `umcf-engine-ai` |
| **`FR-050`** | `P1` | **Multimodal Vision Encoder Partitioning (LLaVA / Qwen-VL)**: The AI engine SHALL support executing vision encoder patches on a GPU worker and forwarding projected image embeddings into the distributed LLM pipeline. | Submitting an image + text prompt executes the vision encoder stage and streams grounded text responses. | `umcf-engine-ai` |

## Stage 6: Distributed GPU Compute & Media Engine (`FR-051` – `FR-060`)

| Req ID | Priority | Requirement Statement | Acceptance Criteria | Target Component(s) |
| :--- | :---: | :--- | :--- | :--- |
| **`FR-051`** | `P0` | **Cross-Platform `wgpu` Compute Pipeline Execution**: `umcf-engine-media` SHALL execute validated WGSL compute shaders across Vulkan, Metal, DirectX 12, and WebGPU backends with deterministic buffer binding contracts. | Submitting a WGSL matrix/image compute job produces matching output buffers stored in CAS across all supported GPU backends. | `umcf-engine-media` |
| **`FR-052`** | `P0` | **WGSL Shader Validation & Watchdog Bounding**: All submitted WGSL shaders SHALL be parsed and validated via `naga` with bounded dispatch dimensions and a hard per-dispatch execution timeout (`<= 5,000ms`). | Malformed shaders or dispatches exceeding maximum workgroup limits are rejected prior to GPU submission with `MediaError::ShaderValidationFailed`. | `umcf-engine-media` |
| **`FR-053`** | `P0` | **GOP-Aligned Distributed Video Splitter**: For distributed video transcoding, the media engine SHALL split source video containers at keyframe Group-of-Pictures (GOP) boundaries into independent CAS chunks. | Splitting a 60-second video produces independent GOP segment descriptors that can be transcoded in parallel without inter-segment frame dependencies. | `umcf-engine-media` |
| **`FR-054`** | `P0` | **Hardware-Accelerated Parallel Segment Transcoding**: Workers SHALL transcode assigned GOP segments into target codecs (`H.264`, `HEVC`, `AV1`) using available hardware encoders (`NVENC`, `AMF`, `QSV`, `VideoToolbox`, `MediaCodec`) or CPU fallback. | Transcoding a multi-segment job across 3 workers completes in parallel and reports per-segment FPS and output CAS hashes. | `umcf-engine-media` |
| **`FR-055`** | `P0` | **Lossless Media Segment Concatenation & Audio Muxing**: Upon completion of all GOP segment tasks, the coordinator/designated worker SHALL mux transcoded video segments and audio tracks into a frame-accurate output container. | The reassembled output video has identical frame count and A/V sync within `< 1ms` of a single-node reference encode. | `umcf-engine-media` |
| **`FR-056`** | `P1` | **Distributed Tile / Frame 3D & Image Rendering**: Batch rendering jobs SHALL partition frame ranges or 2D image tiles across available GPU workers and composite completed tiles in CAS. | A 4-tile image compute job distributes 1 tile to each of 4 workers and assembles the final composite image without seam artifacts. | `umcf-engine-media` |
| **`FR-057`** | `P1` | **Compiled Pipeline & Shader Binary Caching**: Workers SHALL cache compiled native pipeline states (SPIR-V/DXIL/Metal Archive) keyed by `(shader_blake3, driver_version)` to eliminate repeated shader compilation stalls. | Second execution of an identical shader bypasses compilation and reduces pipeline setup latency by `>= 80%`. | `umcf-engine-media` |
| **`FR-058`** | `P1` | **Dynamic Straggler Speculative Re-Dispatch**: If a slow worker fails to complete the final GOP segment within `2.0x` the median segment duration, the scheduler SHALL speculatively dispatch that segment to an idle fast worker. | Injecting a `10s` delay on 1 of 4 media workers triggers speculative execution on a fast peer, preventing tail-latency stall. | `umcf-scheduler`, `umcf-engine-media` |
| **`FR-059`** | `P1` | **Batch Audio Transcription & Processing Pipeline**: Audio files SHALL support Voice Activity Detection (VAD) segmentation and parallel transcription/processing across workers. | Long-form audio is segmented at silence boundaries and processed concurrently across workers. | `umcf-engine-media`, `umcf-engine-ai` |
| **`FR-060`** | `P1` | **Output Quality Verification Check**: Transcoded media segments SHALL verify container integrity, non-zero frame counts, and duration accuracy before marking the task lease `Completed`. | Truncated or zero-frame encoder outputs are automatically rejected and rescheduled on a healthy worker. | `umcf-engine-media` |

## Stage 7: Low-Latency Remote Desktop, Application & Game Streaming Engine (`FR-061` – `FR-070`)

| Req ID | Priority | Requirement Statement | Acceptance Criteria | Target Component(s) |
| :--- | :---: | :--- | :--- | :--- |
| **`FR-061`** | `P0` | **Zero-Copy Display & Window Surface Capture**: Host nodes SHALL capture desktop or specific application windows via low-overhead OS APIs (`DXGI Desktop Duplication` on Windows, `PipeWire`/`DRM` on Linux, `ScreenCaptureKit` on macOS) at up to `120 FPS`. | Frame capture loop acquires GPU texture handles in `<= 2.0ms` per frame without CPU framebuffer readback when hardware encoding is active. | `umcf-engine-stream` |
| **`FR-062`** | `P0` | **Ultra-Low-Latency Hardware Video Encoding**: Captured frames SHALL be encoded using zero-B-frame, single-pass `LowLatency`/`UltraLowLatency` profiles (`H.264`, `HEVC`, `AV1`) with periodic intra-refresh macroblock waves. | Hardware encoder latency per 1080p frame is `<= 4.0ms` on supported GPUs with zero multi-frame lookahead buffering. | `umcf-engine-stream` |
| **`FR-063`** | `P0` | **QUIC Datagram & WebRTC Media Transport with FEC**: Encoded video NAL units and Opus audio frames SHALL be transmitted over QUIC Datagrams (or WebRTC RTP for browsers) protected by adaptive Reed-Solomon Forward Error Correction (`FEC`). | Under `1.5%` simulated random UDP packet loss, the receiver reconstructs missing packets via FEC without requiring full IDR frame retransmissions. | `umcf-engine-stream` |
| **`FR-064`** | `P0` | **High-Frequency Authenticated Input Return Channel**: Client nodes SHALL transmit keyboard, mouse (relative & absolute), multi-touch, and gamepad events over a high-priority (`Priority = 1`) stream/datagram channel to the host OS input injector. | Input events carrying a valid `stream:input` capability scope are injected into the host OS within `< 2.0ms` of LAN client action; unauthorized inputs are dropped. | `umcf-engine-stream` |
| **`FR-065`** | `P0` | **Adaptive Bitrate & Congestion Control (AIMD / GCC)**: The streaming engine SHALL dynamically adjust encoder bitrate (`2 Mbps .. 80 Mbps`), resolution scale, and FPS based on real-time receiver jitter, decode time, and packet loss feedback. | Halving simulated link bandwidth triggers smooth encoder bitrate adaptation within `<= 500ms` without stalling the video stream. | `umcf-engine-stream` |
| **`FR-066`** | `P1` | **Low-Latency Synchronized Opus Audio Streaming**: Host desktop/application audio loopback SHALL be captured in `5ms` or `10ms` frames, Opus-encoded, and synchronized with video presentation timestamps. | Audio-to-video lip-sync drift remains within `±15ms` over a 30-minute streaming session. | `umcf-engine-stream` |
| **`FR-067`** | `P1` | **Multi-Viewer Broadcast & Cooperative Control Mode**: A host streaming session SHALL support multiple simultaneous viewers with independent `stream:view` vs. `stream:input` permissions (e.g., multiplayer controller pass-through). | Two connected clients receive the same encoded video stream while the host owner can toggle input control per client in real time. | `umcf-engine-stream` |
| **`FR-068`** | `P1` | **Bidirectional Encrypted Clipboard & Drag-and-Drop File Transfer**: Authorized remote desktop sessions SHALL support opt-in text clipboard synchronization and CAS-backed file drop between client and host. | Copying text on the client updates the host clipboard when enabled; dragging a file transfers it via BLAKE3 CAS chunks. | `umcf-engine-stream`, `umcf-engine-storage` |
